# 카드뉴스 각색기 (쿠팡파트너스용)

인스타그램 카드뉴스(캐러셀) 게시물 주소를 넣고 버튼 하나를 누르면,
슬라이드 글·캡션을 **원본과 다르게 각색**하고 깔끔한 디자인을 입혀 PNG로 내려받는 웹앱입니다.
50~60대도 혼자 쓸 수 있도록 큰 글씨·큰 버튼·한 화면 한 단계로 만들었습니다.

**화면 구성은 기기에 맞춥니다.** PC(가로로 넓음)에서는 바뀌는 걸 **한눈에** 보도록 가로로 펼치고,
모바일(세로로 김)에서는 세로로 쌓되 미리보기가 화면 위에 붙어 따라다닙니다.

| | PC (≥980px) | 모바일 |
|---|---|---|
| 템플릿 고치기 | 왼쪽 미리보기 **고정** + 오른쪽 설정 | 미리보기가 위에 **붙어서** 따라다님 (작게) |
| 슬라이드 확인 | 가로로 나란히 (3장 이상 한 화면) | 가로로 밀어서 넘김 (스냅) |
| 캡션·고정댓글·DM | 3단 나란히 | 세로로 |

## 사용 흐름

1. **주소 넣기** → `카드뉴스 새로 만들기` 버튼
2. 자동으로 게시물 사진·캡션을 가져온 뒤, **글 각색과 모든 장의 AI 새 사진을 동시에** 돌립니다
   - 사진 편집은 원본 사진만 있으면 되므로 각색을 기다릴 필요가 없습니다. 그래서 전체 시간이 **둘 중 느린 쪽 하나**로 끝납니다
   - 완성본이 한 번에 나오므로 장마다 버튼을 누를 필요가 없습니다 (**항상 이렇게 동작합니다.** 화면에 켜고 끄는 선택지는 두지 않았습니다)
   - 기다리는 동안의 안내 문구에는 **안에서 뭘 하는지(사진 몇 장을 만드는지 등)를 드러내지 않습니다.** 진행감만 주는 문구로 바뀝니다
   - 어떤 장이 실패해도 그 장만 원본 사진을 쓰고 나머지는 그대로 진행합니다
   - 자동 추출이 실패하면 **사진 직접 올리기 + 원문 붙여넣기** 화면으로 자동 안내
3. **미리보기**에서 **디자인 템플릿** 고르기, 마음에 안 드는 장만 `✨ AI 새 사진` 다시 누르거나 `↩ 이전 사진으로` 원본 복귀, 글 직접 수정(1번=표지 제목, 2번부터=본문), 워터마크 문구·캡션 수정
4. **승인하고 내려받기** → `slide_01.png …` (1080×1350) + `caption.txt` + `pinned_comment.txt` + `dm.txt` 를 zip으로 저장
   (휴대폰은 완성 사진을 눌러 한 장씩 저장 가능)

캡션은 **[템플릿 CTA 윗줄] → [AI가 쓴 본문 3문장] → [템플릿 CTA 아랫줄] → [쿠팡 파트너스 고지]** 순으로 조립됩니다.

## 슬라이드 디자인

저장소 루트의 레퍼런스 4장(`ref-slide1-cover.jpg` ~ `ref-slide4-cta.jpg`)을 픽셀 측정해 그대로 옮겼습니다 (`components/SlideCard.tsx`).

- 공통: 1080×1350, 배경에 그 장의 사진을 꽉 차게, 오른쪽 위 `[광고]`(쿠팡 파트너스 고지), 아래 가운데 워터마크(기본 `맛집도둑`, 템플릿에 저장되고 편집 화면에서도 수정 가능)
- 1번 장(표지): 큰 흰 제목, 검은 외곽선·그림자, 박스 없음, 아래쪽 왼쪽 정렬
- 2번 장부터: 아래 가운데 반투명 박스(레퍼런스 측정값: 흰색 48% + 얇은 검은 테두리) 안에 흰 글씨 가운데 정렬
- 글꼴: 제목·본문 [Jua](https://fonts.google.com/specimen/Jua)(둥근 굵은 고딕, SIL OFL), `[광고]`·워터마크 Pretendard
- 글이 길면 글자 크기를 자동으로 줄입니다

## 디자인 템플릿

위 디자인은 **기본 제공 템플릿 "기본 디자인"**이고, 글꼴·색·글상자·워터마크를 바꾼 **내 템플릿**을 만들어 저장할 수 있습니다
(`/templates` 탭, 또는 편집 화면의 `🎨 템플릿 만들기 · 고치기`).

- **표지(1번 장)와 내지(2번 장부터)를 따로** 설정: 글꼴, 글자 크기(작게/보통/크게), 글자색, 글자 테두리, 글 위치(위·가운데·아래), 글 정렬, 글상자(사용 여부·색·진하기·테두리)
- **워터마크**: 문구·글꼴·색·진하기·위치(아래 가운데 / 아래 왼쪽 / 위 왼쪽). 문구는 템플릿에 함께 저장돼 다음에도 그대로 나옵니다
- **캡션 CTA**: 인스타 본문 글의 **맨 윗줄·맨 아랫줄** 문구를 직접 정합니다. 가운데 본문만 AI가 씁니다
  (예: 맨 윗줄 `🤤 댓글에 '나도' 남겨주세요!` / 맨 아랫줄 `💬 레시피 궁금하면 댓글 남겨주세요! 👉`)
- **고정 댓글**: 게시물에 고정해 둘 댓글 문구 (AI가 쓰지 않고 그대로 나옴)
- **자동 DM**: 맨 아랫줄(버튼 안내)을 정합니다. 첫 줄은 고정, 가운데 레시피는 AI가 씁니다
- 오른쪽 위 `[광고]`는 쿠팡 파트너스 고지라 **끌 수 없습니다**
- 기본 제공 3종(`기본 디자인`, `굵은 자막형`, `깔끔한 흰 박스`)은 고칠 수 없고 **복제**해서 쓰며, 내가 만든 템플릿은 몇 개든 저장·수정·삭제할 수 있습니다
- 저장 위치는 **이 브라우저**(localStorage: `cardnews.templates.v1`, 고른 템플릿은 `cardnews.template.active`) — 서버에 올라가지 않습니다
- 편집 화면에서 템플릿을 고치면 **겹쳐서** 열립니다. 만들던 카드뉴스가 사라지지 않게 하려는 것입니다

### 글꼴

내장 2종(주아·프리텐다드) + jsDelivr CDN([fonts-archive](https://github.com/fonts-archive))에서 내려받는 12종.
고른 글꼴만 그때 내려받고(`lib/webfonts.ts`의 `ensureFont`), PNG로 저장할 때 글꼴을 그림 안에 심습니다(CORS 허용 CDN이라 가능).

| 용도 | 글꼴 |
|---|---|
| 둥근 고딕 | 주아(내장·기본), 비둘기마요 |
| 굵은 제목 | 도현, 지마켓 산스, KCC 간판체, 강원교육 파워, 강원교육 모두 |
| 가는 고딕·명조 | 카페24 오스퀘어 에어, 마루부리, 프리텐다드(내장) |
| 손글씨 | HS봄바람 3.0, 강원교육 현옥샘, 강원교육 새움 |
| 영문 | Helvetica Neue(기기 글꼴) |

> 요청받은 목록 중 **KoreanCNML·BBTreeG_B·HYHeadLine-Medium**은 무료 웹폰트 CDN에 없어 넣지 못했습니다(상용 라이선스로 보입니다).
> 쓰려면 웹폰트 파일을 직접 구해 `app/fonts/`에 넣고 `lib/webfonts.ts`에 추가하면 됩니다.

## 고정 댓글

게시물에 올리고 맨 위에 고정해 둘 댓글입니다. AI가 쓰지 않고 **템플릿에 적어 둔 문구가 그대로** 나옵니다.
편집 화면 ⑤에서 확인·수정하고, 승인하면 `pinned_comment.txt` 로 zip에 들어갑니다.

```
💬 레시피 궁금하면 댓글에 '나도' 남겨주세요!
👉 프로필 링크 들어가서 <0 or 재료> 검색해도 확인 가능해요!
🙏 DM 못 받으신 분들은 새 댓글 남겨주세요
```

`<0 or 재료>` 는 머닝 같은 자동 DM 도구에서 쓰는 키워드 자리라 **그대로 둡니다.** 숫자·키워드는 직접 고치세요.

## 자동 DM

댓글 단 사람에게 보내는 **레시피 DM 문구**도 함께 만듭니다. 편집 화면 ⑤에서 보고 고칠 수 있고,
승인하면 `dm.txt` 로 zip에 같이 들어갑니다.

```
댓글로 요청하신 레시피 드립니다!   ← 고정 (바꿀 수 없음)

🌶️ 즉석 떡볶이 비법 양념장      ← AI

🍯 물엿 5T
🍚 설탕 2T
✨ 비밀재료 2T                 ← AI (정확히 한 줄)
🧂 후추 약간

🧑‍🍳 만드는 법                  ← 고정

1️⃣ 모든 양념 재료를 넣고 골고루 섞어주세요.   ← AI (번호 이모지는 앱이 붙임)

2️⃣ …

💡 비밀재료를 꼭 넣어야 감칠맛이 터져요!      ← AI

[맨 아랫줄 버튼 안내]           ← 템플릿에서 설정 (기본: "👇비밀 재료는 하단 버튼 클릭 후 / <0 or 재료> 검색해주세요!")

*쿠팡파트너스 활동의 일환으로 …*  ← 고정
```

- **비밀재료 규칙(핵심)**: 재료 목록에 `✨ 비밀재료 2T` 가 **정확히 한 줄** 들어가고,
  **그게 무엇인지는 절대 쓰지 않습니다.** 정체를 암시하는 것도 금지입니다 —
  그걸 알려면 링크를 눌러야 하는 게 이 DM의 장치이기 때문입니다 (테스트로 자동 확인).
- 재료는 줄마다 어울리는 이모지 + 집에서 쓰는 단위(T·t·봉·개·약간), 단계는 존댓말 `~세요`,
  마지막 단계만 `~완성!` 으로 맺습니다.
- 캡션과 마찬가지로 **서버는 레시피만 돌려주고 조립은 화면에서** 하므로, 템플릿만 바꿔도 AI 재호출 없이 반영됩니다.
- 첫 줄은 **고정**입니다 (반말이 섞이지 않게). 사용자가 정하는 건 맨 아랫줄 버튼 안내뿐입니다.

## 인스타 게시물 가져오기 (차단 뚫기)

인스타는 서버에서 바로 받으면 **데이터가 없는 껍데기 HTML**만 돌려줍니다 (클라우드 IP는 더 심함).
실측해 본 결과:

| 방법 | 결과 |
|---|---|
| `i.instagram.com/api/v1/media/{id}/info` | `login_required` (403) |
| `www.instagram.com/api/v1/media/{id}/info` | 로그인으로 302 |
| 임베드 페이지 직접 요청(`fetch`) | 200이지만 **미디어 데이터 0** (JS 껍데기) |
| 임베드 페이지 직접 요청(`node:https`) | ✅ **캐러셀 전체 + 캡션 전문** |
| ddinstagram / kkinstagram 미러 | 접속 불가 |
| **r.jina.ai 로 임베드 페이지 렌더링** | ✅ **캐러셀 10장 전체 + 캡션 전문** |

### 왜 `fetch` 로는 안 되는가 (핵심)

**`fetch`(undici)는 스펙대로 `Sec-Fetch-Mode` 를 항상 `cors` 로 덮어씁니다.**
인스타는 이 값이 `navigate` 가 아니면 데이터 없는 껍데기를 돌려줍니다.
헤더를 아무리 맞춰도 `fetch` 로는 뚫리지 않아서, 헤더를 그대로 보낼 수 있는
**`node:https` 로 직접 요청**합니다 (`rawGet`). 브라우저와 같은 헤더 세트
(`Accept` / `Accept-Language` / `Sec-Fetch-Dest: iframe` / `Sec-Fetch-Mode: navigate` /
`sec-ch-ua*` / `Referer`)를 통째로 보내야 합니다 — 일부만 보내면 또 껍데기가 옵니다.

그래도 실패하면 **`r.jina.ai` 가 자기들 브라우저로 임베드 페이지를 열어 렌더링한 HTML**을 받아옵니다.
그 안에는 `contextJSON`(= GraphQL 원본 데이터)이 그대로 들어 있어서 캐러셀 전체와 고해상도 이미지(1238~1440px)를 얻습니다.
느리니(10~30초) 직접 요청이 실패했을 때만 씁니다.
⚠️ 키 없이 쓰면 **다른 사용자의 남용 때문에 도메인 단위로 몇 시간씩 막힐 수 있습니다**(403 `AbuseAlleviationError`).
그때는 `JINA_API_KEY` 를 넣으면 익명이 아니게 되어 풀립니다.

## 글 스타일 (레퍼런스 분석 결과)

레시피 카드뉴스 레퍼런스 **5세트(20장) + 캡션**을 분석해 뽑은 규칙을 각색 프롬프트(`lib/remix.ts`)에 그대로 넣었습니다.

| | 슬라이드 글 | 캡션 본문 |
|---|---|---|
| 말투 | **반말 구어체** (친구한테 맛집 자랑하듯, 1인칭 체험담) | **존댓말 `~요`체** |
| 이모지 | **절대 안 씀** (사진 위 글씨라 깨짐) | **문장마다 끝에 1개** (서로 다른 걸로) |
| 분량 | 표지·내지 모두 **정확히 3줄** | **정확히 3문장** |
| 글자 수 | 표지 한 줄 6~14자 / 내지 한 줄 12~18자 | — |

- **표지(1번 장) 3단 구조**: ①권위(매출·지역·유명세) ②메뉴 이름 ③공개 선언
  → `월 1억 매출 한정식집 / 줄 서서 먹는 소고기 구이 / 비밀 레시피 공개`
  원본에 매출·가게 정보가 없으면 **지어내지 않고** "줄 서서 먹는", "유명한" 같은 표현으로 채웁니다.
- **내지 어미**: `~잖아 / ~없어 / ~더라 / ~지 / ~네 / ~임 / ~해짐`, 말줄임표 `...`·`!!!`·`;;;`·`ㅠ` 를 장당 1~2개까지
- **내지 역할**: 2번=첫입 감탄·공감 / 3번=맛·식감·비법 / 4번 이후=활용·보관 / 마지막 장=마무리 + **마지막 줄만** 댓글 유도
- **캡션 3문장 역할**: ①어디서 먹던 음식 + 집에서도 된다는 공감 ②핵심 조리 포인트 한 가지 ③활용도·가치
- 캡션의 CTA 두 줄과 쿠팡 고지는 AI가 쓰지 않고 **앱이 템플릿 설정대로 앞뒤에 붙입니다** (`lib/caption.ts`)

## AI (OpenAI)

| 용도 | 모델 (기본값) | 호출 위치 |
|---|---|---|
| 사진 속 글씨 읽기(vision) + 각색 | `gpt-5-mini` — Responses API, 구조화 출력(JSON 스키마) | `lib/remix.ts` |
| AI 새 사진 ① 원본 사진 분석 | `gpt-5-mini` — 비전, 구조화 출력 | `lib/image-gen.ts` |
| AI 새 사진 ② 같은 요리를 새로 생성 | `gpt-image-2.5-sunburst` — Images API generations (분석 실패 시 edits) | `lib/image-gen.ts` |

> ⚠️ OpenAI 공지 기준 **`gpt-5-mini`는 2026-12-11 지원 종료 예정**입니다. 그 전에 `OPENAI_TEXT_MODEL`만 바꾸면
> 코드 수정 없이 교체됩니다 (OpenAI 권장 후속: `gpt-5.6-terra`). 사진 모델도 `OPENAI_IMAGE_MODEL`로 교체 가능합니다.

### AI 새 사진

- **각색을 시작하면 모든 장의 사진을 글 각색과 병렬로 한꺼번에 만듭니다.** 기본 동작이며 화면에서 끌 수 없습니다
  (아예 기능을 빼려면 `NEXT_PUBLIC_ENABLE_IMAGE_GEN=0`). 장 수만큼 비용이 드니 월 한도를 꼭 걸어 두세요.
  실패한 장은 원본 사진을 유지하고 자동 재시도하지 않습니다.
- 편집 화면의 `✨ AI 새 사진` 버튼은 마음에 안 드는 장만 다시 만들 때 씁니다.
- 목표: **원본처럼 사실적이지만 구도·배경·배치만 바뀐, 글자 없는 깨끗한 사진**.
- **분석 후 새로 촬영(기본)**: 지금 사진을 비전 모델이 분석해(요리·재료·**사진 느낌**) 같은 요리를 **새로** 만듭니다.
  원본 사진을 이미지 모델에 넣지 않기 때문에 구도·재료 배치가 **실제로** 달라집니다.
  > ⚠️ 실측 결과: 편집(img2img) 방식은 "한눈에 다르게 바꿔라"를 아무리 강하게 써도 **입력 이미지 구조에 고정**돼
  > 재료 배치가 거의 그대로 남았습니다. 구도를 진짜로 바꾸려면 원본을 넣지 않고 새로 생성해야 합니다.
  > 사실감은 프롬프트의 미화 금지 규칙 + 분석이 뽑아낸 `photo_look_en`(원본의 조명·색감·선명도·분위기)으로 지킵니다.
- **편집 방식**(`OPENAI_IMAGE_MODE=edit`): 그 장의 지금 사진을 이미지 편집 모델에 넣어, 같은 요리·같은 재료·같은 사진 느낌(질감·조명·색감·분위기)은 유지하고
  **아래 다섯 축을 한꺼번에** 바꿉니다. 한 축만 바꾸면 원본과 너무 비슷해 보여서, 매번 다섯 개를 각각 따로 뽑습니다.

  | 축 | 바뀌는 것 |
  |---|---|
  | 앵글 | 위에서(90°) / 45° / 테이블 높이 / 가까운 클로즈업 — 원본 앵글은 제외 |
  | 얼마나 가까이 | 몇 조각이 화면을 다 채울 만큼 / 그릇 테두리가 잘릴 만큼 / 테이블이 살짝만 보일 만큼 (**전부 가까운 쪽**) |
  | 가운데 오는 것 | 한 조각 / 젓가락에 집힌 조각 / 양념이 제일 두껍게 묻은 부분 / 속이 보이는 단면 |
  | **재료 배치** | 앞뒤 재료 자리 바꾸기 / 그릇 돌려 다른 재료가 정면에 / 덜 정갈하게 섞인 모습 / 다른 부분이 가장 잘 보이게 |
  | 살짝 보이는 배경 | 평범한 식당·집 테이블 4종 (가장자리에만) |

  **구도는 변화 축이 아니라 고정 제약입니다**: 음식이 화면의 85% 이상을 채우고 한가운데.
  접시·팬 테두리는 잘려도 되지만, 테이블·바닥·배경이 넓게 보이거나 음식이 작게 한쪽으로 치우치면 안 됩니다.
  (이 제약을 안 박아 두면 그릇이 작게, 테이블만 넓게 나옵니다 — 실측 확인)
  원본이 **조리 과정 4분할 같은 콜라주**면 그 레이아웃은 유지하고 각 칸의 사진만 바꿉니다.

  "원본 구도를 따라 하지 말고 한눈에 다른 사진이어야 한다"를 명시합니다. 누를 때마다 조합이 달라집니다.
- **사실감**: "실제로 찍은 사진처럼, AI 티 안 나게, 미화·보정·스타일라이즈 금지, 원본의 실제 질감·분위기 유지"를 명시합니다.
  '더 맛있게·전문 푸드포토·윤기·김·생생한 색감' 같은 미화 표현은 쓰지 않습니다 (테스트로 자동 확인).
- **글자·그래픽 제거**: 텍스트·자막·워터마크·`[광고]`·하단 그라데이션·반투명 텍스트박스·테두리를 모두 지우고, 가려졌던 부분은 실제 음식·테이블로 자연스럽게 채우라고 명시합니다 (영문 + 한글).
- 분석이 실패하면 자동으로 편집 방식으로 대체합니다.
- 사진이 없는 장은 글 내용으로 새로 만듭니다.
- 출력: `gpt-image-2.5-*`는 정확히 4:5인 1088×1360으로 받고(그 외 모델은 1024×1536), 브라우저에서 1080×1350으로 꽉 차게 잘라 배경을 교체합니다.
- 만드는 중엔 미리보기 위에 로딩 표시, 실패하면 한글 안내, `↩ 이전 사진으로` 되돌리기 가능.
- 모델 선택: `gpt-image-1`은 이미 서비스 종료, `gpt-image-1-mini`는 2026-12-01 종료 예정이라, 편집 정밀도가 가장 높다고 안내된 `gpt-image-2.5-sunburst`를 기본값으로 했습니다.

### 비용 (월 $3, 하루 1건·4장 기준)

저비용 설정: 각색은 `reasoning.effort: low`, 출력 상한 8,000토큰, 재시도 1회. AI 사진은 `low` 품질, 버튼을 누를 때만 1장씩, 재시도 없음.

| 항목 | 1건(4장) 대략 | 한 달(30건) 대략 |
|---|---|---|
| 각색 (gpt-5-mini, 입력 $0.25 / 출력 $2 per 1M) | 약 $0.005~0.02 | 약 $0.15~0.6 |
| AI 새 사진 자동 생성(항상) | **장 수만큼** (4장 = 4번 호출) | 아래 참고 |
| AI 새 사진 (gpt-image-2.5-sunburst, low) | 장당 가격 미공개 | 아래 참고 |

AI 새 사진은 OpenAI가 장당 가격을 공개하지 않고 토큰 단가(사진 입력 $8 / 사진 출력 $30 per 1M)만 공개합니다.
처음 몇 장을 만든 뒤 대시보드 Usage에서 실제 장당 비용을 확인하세요. 월 $3 안에 맞추기 빠듯하면
`OPENAI_IMAGE_MODEL=gpt-image-1-mini`(토큰 단가 약 1/4, low 출력 장당 약 $0.006 + 입력, 단 2026-12-01 종료 예정)로 바꿀 수 있습니다.
각색 쪽 사진 입력 토큰 수도 해상도에 따라 달라지므로 위 수치는 추정치입니다. **실제 한도는 OpenAI 대시보드에서 거세요**:
platform.openai.com → Settings → Limits(프로젝트 Budget)에서 월 $3로 설정. 한도를 다 쓰면 앱은
"이번 달 사용 한도를 다 쓴 거예요" 안내를 보여주고, 수동 편집·다운로드는 그대로 쓸 수 있습니다.

## 로컬 실행

```bash
npm install
cp .env.local.example .env.local   # OPENAI_API_KEY 입력
npm run dev
```

키 없이 화면만 보려면 `.env.local`에 `MOCK_LLM=1`을 넣고 실행하세요 (예시 문장·예시 사진).

## 테스트

```bash
npm run build
npm run test:ai    # 가짜 OpenAI 서버로 각색·AI 새 사진의 요청 형식(원본 사진·크기·글자 제거 지시)과 오류 처리 확인
npm run test:e2e      # 데모 모드로 화면 전체 흐름(업로드→각색→수정→zip 다운로드) 확인, Playwright 필요
npm run test:template # 템플릿 만들기→저장→편집 화면 적용→PNG 저장→삭제 확인 (CDN 글꼴을 받아오므로 인터넷 필요)
```

Playwright는 저장소 의존성에 넣지 않았습니다. 테스트 전에 `npm i -D playwright --no-save && npx playwright install chromium`을 한 번 실행하세요.

## Vercel 배포

1. 이 저장소를 Vercel에 Import
2. Settings → Environment Variables 에 `OPENAI_API_KEY` 추가
3. Deploy

| 환경변수 | 필수 | 설명 |
|---|---|---|
| `OPENAI_API_KEY` | ✅ | OpenAI API 키 |
| `OPENAI_TEXT_MODEL` | | 기본 `gpt-5-mini` |
| `OPENAI_IMAGE_MODEL` | | 기본 `gpt-image-2.5-sunburst` (이미지 입력=편집 지원 모델이어야 함) |
| `OPENAI_IMAGE_QUALITY` | | `low`(기본) / `medium` / `high`. 질감이 뭉개져 보이면 `medium` (비용 증가) |
| `OPENAI_IMAGE_MODE` | | `describe`(기본, 분석 후 새로 생성 — 구도가 실제로 달라짐) / `edit`(원본 사진 편집 — 질감은 가장 비슷하지만 원본 구도가 거의 그대로) |
| `NEXT_PUBLIC_ENABLE_IMAGE_GEN` | | 기본 켜짐. `0`이면 'AI 새 사진' 버튼 숨김. 바꾸면 **재배포** 필요 |
| `IG_DOC_ID` | | 인스타 GraphQL doc_id. 인스타 변경으로 자동 추출이 깨지면 교체 |
| `JINA_API_KEY` | | r.jina.ai 호출 한도를 늘릴 때 (없어도 동작) |
| `MOCK_LLM` | | `1`이면 데모 모드. **실서비스에선 비워 두기** |

`/api/remix`는 30초~1분 걸릴 수 있어 `maxDuration = 120`, `/api/image-gen`은 1~2분 걸릴 수 있어 `maxDuration = 240`으로 두었습니다
(요금제별 함수 최대 실행 시간을 확인하세요).

## 알려진 한계

- 인스타그램 자동 추출은 인스타 측 구조 변경에 따라 깨질 수 있습니다. 이때는 수동 경로를 쓰면 됩니다.
- AI 새 사진은 글씨 없는 배경 사진만 만듭니다. 글씨는 앱의 디자인 템플릿이 위에 얹습니다. AI가 드물게 글자 흔적을 남길 수 있으니 결과를 보고 마음에 안 들면 다시 누르거나 되돌리세요.
